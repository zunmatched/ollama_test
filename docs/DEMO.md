# 五分鐘展示與操作指南

## 展示前

1. 插上電源，確認 `data/demo/stocks.sqlite` 存在。
2. 雙擊 `start-demo.cmd`，等待右上角顯示本機服務就緒。
3. 先執行「查行情」暖機；核對模型顯存占用。
4. 事先手動中斷網路，重跑查詢，再恢復網路。這一步是現場離線演練，不由腳本改動網路設定。
5. 執行 `uv run python scripts/smoke_demo.py`，保留 `docs/local-results/demo-backup.html`。
6. 明天出門前從關閉服務的狀態再啟動一次。正常重啟測試不代表已驗證整台 Windows 重新開機。

## 五分鐘講解

**0:00–0:40 問題與資料。** 以自己的股票資料展示企業資料助理的通用流程。資料先由 PostgreSQL 唯讀匯出到 SQLite，現場不依賴遠端連線。

**0:40–1:20 架構。** 本機 Qwen3 選工具；Python 驗證參數與執行固定 SQL；工具結果回到模型產生回答。網頁只呈現可觀察的工具步驟，不是模型內部思考。

**1:20–2:20 查行情。** 點「查行情」再送出。展開右側 `get_prices`，核對代號、資料日期與五筆收盤價。

**2:20–3:20 比較。** 點「比較價格」。解釋程式對齊共同交易日，用 `(期末 / 期初 - 1) × 100` 計算，模型只說明結果。這是未驗證還原方式的價格變化，不是總報酬。

**3:20–4:10 資料不足。** 點「資料不足」。工具應回傳空資料，模型不得拿其他日期代替。這個案例展示可控失敗。

**4:10–5:00 限制與延伸。** 說明實測速度、4B 模型的限制與工具白名單。若有時間再展示新聞：300 則可做向量搜尋；圖譜只抽取最新 30 則，其中 8 則有原文證據。現場展開工具紀錄，說明實際用了哪種檢索。

## 可直接練習的問題

- 查詢台積電（2330）最近五個交易日的收盤價。
- 比較 2330 和 2303 在 2026-09-01 至 2026-09-21 的價格變動百分比。
- 搜尋「記憶體」最近三則新聞，整理重點並附來源日期。
- 查詢 2330 在 2030-01-01 的收盤價，只查這一天。
- 先查詢台積電的代號，再查它最近三個交易日的行情。

固定日期問題只適用目前快照。重新匯出後以畫面截止日期為準。

## 故障備援

- **模型未就緒：** 查看 `.runtime/ollama-error.log`，確認 `qwen3.5:4b` 已依 README 下載。若要切回備援，執行 `scripts/start.ps1 -Model stock-agent:4b`。
- **網頁無法開啟：** 重跑啟動器，查看 `.runtime/web-error.log`。
- **推論很慢：** 先檢查電源與顯存；不要現場換模型。第一次載入時間不等於暖機後速度。
- **回答不準：** 展開工具結果核對，承認模型輸出限制，改用較具體的問法。
- **服務失敗：** 直接開啟 `docs/local-results/demo-backup.html`，明確說明是先前實測紀錄。

## 面試說法

這是個人筆電上的部署與工具呼叫驗證；既有企業 RAG／agent 經驗另行介紹。不要把本 demo 說成正式企業部署，也不要把提示詞約束說成完整安全隔離。

可延伸討論：資料更新排程、權限篩選、稽核、檢索評估、多使用者排隊、容器化及 GPU 容量規劃。
