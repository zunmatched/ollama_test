# 實測結果

測試日期：2026-09-22。此處只保存方法與效能摘要，原始行情、新聞和模型回答僅存本機 `docs/local-results/`。

## 環境

- Windows，RTX 4070 Laptop GPU，8 GB VRAM。
- Ollama 0.34.2；雲端功能關閉，服務綁定 loopback。
- Qwen3 4B Instruct 2507 Q4_K_M，來源模型 ID `0edcdef34593`。
- 本機別名 `stock-agent:4b`，使用 repository 的相容工具模板。
- `num_ctx=8192`、`temperature=0`、最多 5 輪。
- `ollama ps` 顯示 100% GPU，模型載入約 3.9 GB；這不包含桌面及其他程式顯存。

## 驗證

`uv run pytest -q`：**28 項通過**，含唯讀限制、參數／日期驗證、共同交易日計算、模型工具迴圈、最大輪數、比較修正與來源 ID 檢查。測試套件另有兩個上游棄用警告，沒有測試失敗。

真模型固定案例的最後一輪結果如下。模型已載入，為單次暖機後觀察值，不是平均值或 P95：

| 案例 | 總耗時 | 結果 |
|---|---:|---|
| 最近五筆行情 | 3.38 秒 | 工具與五筆收盤價核對一致 |
| 同期間雙股比較 | 2.72 秒 | 使用共同交易日，百分比與程式結果一致 |
| 三則新聞 | 4.44 秒 | 三個來源 ID 完整，摘要依檢索片段；非外部事實查核 |
| 超出快照日期 | 2.21 秒 | 空資料，沒有以其他日期代替 |

初版工具流程檢查曾未能攔截不完整摘要，後續增加完整性檢查並重新驗證。不要將「工具流程通過」解讀為全面的答案正確性保證。

## 離線範圍與限制

已停止本次建立的 Ollama 與網頁服務，再以 `scripts/start.ps1 -NoBrowser` 成功啟動；不是僅在服務已執行時開啟網頁。

推論只呼叫本機 Ollama，資料來自 SQLite；套件、模型與網頁資源已存本機。沒有關閉整台筆電的網路介面，也沒有重啟 Windows，因此實際斷網和開機演練仍應按 DEMO.md 執行。新聞原文連結需外網。

尚未驗證真實多使用者負載、企業權限、所有自然語句、向量檢索或未見資料。新聞原文可能有錯，摘要可能遺漏語境；價格調整方式與成交量單位也尚未確認。

## 較新 Qwen 模型比較

2026-09-23 在同一台 RTX 4070 Laptop 8 GB、`num_ctx=8192`、PostgreSQL 快照與同一套 `run_agent` 上，另外測試 Ollama `qwen3.5:4b`。模型檔 3.4 GB，載入後 `ollama ps` 顯示 100% GPU。`nvidia-smi` 當時顯示 GPU 記憶體使用 5,222 / 8,188 MiB（同時含桌面等其他 GPU 工作）。

| 案例 | Qwen3 4B 舊測值 | Qwen3.5 4B 新測值 | 預期工具 |
|---|---:|---:|---|
| 行情 | 6.86 秒 | 4.06 秒 | `get_prices` |
| 比較 | 3.23 秒 | 3.80 秒 | `compare_stocks` |
| 新聞 | 4.54 秒 | 6.20 秒 | `search_news` |
| 指定日期無資料 | 2.45 秒 | 3.20 秒 | `get_prices` |

每種模型各是單次觀察值。新版四例共 17.26 秒，舊版共 17.08 秒，整體耗時相近；新版在行情案例較快，但新聞與缺資料案例較慢。四例都呼叫預期工具並產生回答，新聞引用欄位存在；沒有做人工逐篇事實核對，也沒有足夠樣本證明品質提升。啟動腳本現在預設 `qwen3.5:4b`，舊模型可用 `-Model stock-agent:4b` 切回。此設定只在目前這台已下載新版模型的筆電可直接啟動；新環境需先 `ollama pull qwen3.5:4b`。
